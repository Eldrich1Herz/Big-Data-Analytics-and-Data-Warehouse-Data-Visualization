Для каждого задания есть свои маппер и редьюсер, комбайнер - для шестого задания.
Все скрипты читают данные из стандартного ввода построчно, обрабатывают их и выводят результат в стандартный вывод.
Перед запуском заданий загружаем тестовые данные в HDFS. Я создала отдельные директории в HDFS для каждого задания и скопировала туда локальные файлы из папки data с помощью команды hdfs dfs -put.
Все скрипты при запуске через Hadoop Streaming обращаются именно к этим путям в HDFS.
Результаты работы каждая задача сохраняет в свою выходную директорию.
Перед каждым новым запуском я удаляю старую выходную директорию, чтобы избежать ошибок.
Запуск всех заданий - через скрипт run_all.sh.
Он проверяет, запущен ли Hadoop, создаёт псевдоним для длинной команды Hadoop Streaming, последовательно выполняет все задания, удаляет старые выходы перед каждым запуском, и выводит результаты в консоль.
Весь вывод сохраняется в лог-файл. Это позволяет один раз запустить скрипт и получить готовый отчёт.

Задание 1. WordCount.
Берем текстовый файл, считаем, сколько раз встретилось каждое слово.
Маппер разбивает строки на слова и выдаёт пары (слово, 1).
Редьюсер суммирует единицы для каждого слова -> сколько раз было слово.

Задание 2. Инвертированный индекс 
Есть несколько документов. Нужно для каждого слова сказать, в каких документах оно встречается.
Маппер читает пару (doc_id, текст) и выдаёт (слово, doc_id).
Редьюсер собирает для каждого слова множество doc_id.
Итого: hello -> doc1, doc2, hadoop -> doc2, world -> doc1.

Задание 3. Среднее по ключу (45 секунд)
Есть данные вида (ключ, значение). Нужно для каждого ключа посчитать среднее арифметическое.
(A,10), (A,20), (B,5), (B,15). Ожидаем: A=15, B=10.
Маппер выдаёт (ключ, значение, 1).
Редьюсер суммирует, затем делит.
Это аналог GROUP BY и AVG в SQL.

Задание 4. Top‑N слов.
Из результата WordCount нужно выбрать 3 самых частых слова.
Маппер просто передаёт пары дальше (ничего не меняет).
Редьюсер использует специальную структуру (кучу), чтобы хранить только топ-3, не запоминая все слова.
Итого: hadoop 3, hello 3, world 2.

Задание 5. Secondary sort 
Для каждого ключа нужно вывести значения в отсортированном порядке.
A:3, A:1, A:2 -> A: 1,2,3.
Маппер создает составной ключ ключ-значение с ведущими нулями, чтобы сортировка происходила автоматически.
Редьюсер собирает значения в порядке прихода.
Hadoop сортирует данные как строки, а не как числа.
Если значения будут просто строками, то порядок будет правильный. Но если значения разной длины (например, 1, 10, 2), то строковая сортировка даст 1, 10, 2, а не 1, 2, 10.
Поэтому надо добавить ведущие нули, чтобы все значения стали одинаковой длины.
{value_int:05d} означает:
05 - всего 5 цифр
d - десятичное число
недостающие цифры заполняются нулями слева.

Задание 6. Combiner 
Добавляем в WordCount комбайнер – это локальный редьюсер, который запускается на стороне маппера.
Комбайнер суммирует частоты слов прямо на том узле, где работал маппер. Это уменьшает объём передаваемых данных по сети.
Результат тот же, что у WordCount, но в логах видно, что Combine input records уменьшились до Combine output records - то есть данных стало меньше.

Задание 7. Join двух таблиц
Есть две таблицы: пользователи (id, имя) и заказы (user_id, товар). Нужно получить для каждого заказа имя пользователя.
Пользователи: (1, Alice), (2, Bob)
Заказы: (1, Book), (1, Pen), (2, Laptop)
Ожидаем: Alice Book, Alice Pen, Bob Laptop.
Маппер помечает каждую запись тегом: U для пользователей, O для заказов.
Редьюсер собирает для каждого id всех пользователей и все заказы, затем делает декартово произведение - выводит все пары (имя, товар).
Это аналог JOIN в SQL.

Задание 8. Data skew
Что будет, если один ключ встречается в 90% данных?
Все записи с этим ключом попадут в один редьюсер, он будет работать очень долго, а остальные редьюсеры простаивают. Может даже не хватить памяти.
Лучше пользовать комбайнер, добавить случайную соль к ключу, чтобы разбить его на несколько частей.

Задание 9. Pipeline (конвейер из двух MapReduce)
Запускаем WordCount, а затем на его результате - Top‑N. Всё автоматически в одном скрипте.
Первый MapReduce (WordCount) пишет промежуточный результат в HDFS.
Второй MapReduce (Top‑N) читает эту папку как вход и выдаёт финальный ответ.
Получаем топ-3 слова, полученные через цепочку.

Задание 10. Почему Hadoop медленный? 
Диск - данные записываются на диск после каждой фазы.
Запуск JVM - каждая задача запускает отдельную виртуальную машину.
Shuffle - сортировка и передача данных по сети - самая долгая фаза.
